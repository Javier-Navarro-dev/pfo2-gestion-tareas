PFO 2 – Sistema de Gestión de Tareas

API REST en Flask con registro, login y página de bienvenida protegida. Los usuarios se guardan en SQLite con contraseñas hasheadas (Werkzeug, scrypt).

Código y documentación completa en el repositorio: ver servidor.py, cliente.py y README.md.

Endpoints

  • POST /registro: 201 / 400 / 409
  • POST /login: 200 / 401
  • GET /tareas: HTML de bienvenida (200) o 401 sin sesión

Capturas de pruebas

1. Registro (201)

2. Usuario duplicado (409)

3. Login con clave incorrecta (401)

4. /tareas sin sesión (401)

5. Login correcto (200)

6. /tareas con sesión (200)

7. Contraseña hasheada en SQLite

Respuestas conceptuales

¿Por qué hashear contraseñas?

Si la base se filtra, las claves en texto plano quedan expuestas y se pueden probar en otros sitios. El hash es de un solo sentido: para validar se hashea lo que ingresa el usuario y se compara. El salt evita tablas precalculadas y un algoritmo lento (scrypt, bcrypt) encarece la fuerza bruta.

Ventajas de SQLite en este proyecto

  • No requiere servidor ni instalación: viene con Python.
  • La base es un único archivo, fácil de copiar y entregar.
  • Cero configuración, ideal para proyectos pequeños y pruebas.
  • Los datos persisten al reiniciar el servidor.
  • SQL estándar con restricciones como UNIQUE y NOT NULL.
